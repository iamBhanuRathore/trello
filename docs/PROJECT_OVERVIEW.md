# PROJECT_OVERVIEW.md — Boardly: What This Project Is and What It Can Do

> Mixed-audience guide (end-user features + architecture). Design docs live in `docs/project.md` (vision, partially superseded), `docs/project-tech-stack.md` (stack decisions), `docs/DATABASE_SCHEMA.md` (76-table reference), `docs/PERMISSIONS_MATRIX.md` (98-key registry), `docs/Glossary.md` (terms), `docs/Roadmap.md` (build order + deferred items), `docs/Progress.md` (session log), `docs/Decisions.md` (ADRs). This file is the readable entry point; those files are the source of truth on details.

**Boardly** is an enterprise multi-tenant Kanban + project-management platform — a Trello/Jira/Asana competitor. One deployment serves many paying companies (**Organizations**), each fully isolated with its own users, workspaces, projects, boards, billing, and branding.

Tenancy hierarchy (see `Glossary.md`): `Organization → Workspace (dept/team) → Project (body of work) → Board (one Kanban) → List (column) → Card (task)`. A Project can hold several Boards (e.g. Planning, Bugs, Content). A Card carries four independent dimensions at once: **List** (where on the board), **Stage** (detailed status label), **Sprint** (which time-box), **Phase** (which lifecycle step).

Three panels: **User panel** (the product), **Company Admin panel** (`/admin/*` — users, billing, branding, security), **Super Admin portal** (standalone SPA on `:5174` — all tenants, plans, platform users, health).

## 1. Everyday work: boards, lists, cards

- **Kanban boards** (`BoardView.tsx`, `dnd-kit` drag-drop, `GET /v1/boards/:id/full` aggregate, OCC `version`-guarded moves with 409 + server truth, `changes?since=` gap-fill on WS reconnect, column virtualization >20 cards). Board/list/card CRUD, archive, clone-with-review (`CloneCardDialog` → `POST /cards/:id/clone`, per-field overrides), sequential ticket keys (`BCW-12`) + `taskNumber`, private tasks (actor-gated reads).
- **Rich card detail** (`TaskDetailView.tsx` dual-pane Bitrix24 layout): Markdown/TipTap description, checklists + items (assignee, due date), comments with @mentions + reactions, attachments (presigned S3 GET, 25 MB cap, virus-scan gate via `requestUpload/confirmUpload`), cover image, due dates, story points, time estimate vs actual bar, labels/tags (board-scoped, same-board enforcement), priorities (org-scoped, drag-ranked), components (board teams like Frontend/Backend), activity feed.
- **Three people roles per card** (distinct avatar groups, distinct notification rules): **Assignee** (does the work, everything notifies), **Participant** (auto-added on comment/attach/@mention/move, comments + major changes), **Watcher/Observer** (self-subscribe, digest-style, read+comment default). Add-user invariant: assignees/participants must be org members; cross-org fails 404 fail-closed (no existence oracle).
- **Subtasks**: self-referencing `parent_card_id`, max 2 levels (Task → Subtask), full card power (assignee, dates, labels), roll-up `subtasks_total/done` on parent, optional auto-complete rule.
- **Views**: Board, Table, Calendar (Month/Week/Day grid, drag time-blocking, `scheduled_start/end` on cards, sprint/milestone overlays), Timeline, Sprint Board, Portfolio (`/workspaces/:id/portfolio` cross-project health), My Tasks (cross-board, `E` archive / `S` snooze / `I` subtask keys), global `Cmd+K` search palette.

## 2. Planning: stages, sprints, phases, calendar

- **Custom Stage templates** (Bitrix24-style, §4c): org-default or per-project templates (`stage_templates` + `stages` with `not_started/in_progress/blocked/done` category for rollups), Stage Manager UI (name/color/order/category), `card.stage_changed` events → feed + notifications + automations.
- **Sprints**: `weekly/biweekly/monthly/custom` per project, `planned/active/completed`, one active sprint per card (history kept for velocity), Sprint Planner UI, burndown/velocity charts (hand-rolled SVG, no chart lib), auto-generate-next-sprint + carry-over (worker).
- **Phases**: project lifecycle (`Discovery → Design → Dev → Test → Launch`), template-able, optional sign-off gates (`phase.sign_off`) for regulated flows.
- **Calendar + sync** (`modules/calendar/`): interactive grid with popovers (press-then-drag distinguishes inspect vs move), per-user Google OAuth (`calendar_connections`, AES-GCM refresh tokens, syncToken incremental pull, on-demand push, `calendar_event_links` for upsert/delete). **Outlook deferred** — same pattern, tracked separately in `Roadmap.md` 4.1.

## 3. Collaboration: chat, inbox, docs, presence

- **Team Chat** (`/chat` + `GlobalChatDock`, `modules/chat/`): 1:1 DMs, public/private/group/task-bound channels, threads, quote-reply, reactions, attachments (staged `chat_attachments` + presigned URL), markdown, typing indicators, online/presence + working-hours/timezone badges, delivery ticks, offline outbox, channel→project linking (`project_id` FK) with system-message activity feed (`card created/moved/archived` fan-out, fire-and-forget so chat never breaks mutations), pin/forward/seen-by (Telegram parity), announcement-only mode, unread via `last_read_at`.
- **Triage Inbox** (`GET /v1/inbox` federated over mentions/review-requests/comments/DMs, starring, keyset paging, trigram search) + **inbound email** (`POST /v1/inbound/email` capability-token receiver: forward-to-create-card, reply-to-comment).
- **Docs/Wiki** (`/projects/:id/docs`, `documents` + `document_cards`): Markdown editor + preview, bidirectional card↔doc linking (the Jira+Confluence moat), full-text via Postgres FTS. **CRDT real-time co-authoring (Yjs/TipTap) + live cursors + embed blocks deferred** (Roadmap 4.4). **WebRTC huddles deferred** (4.5).
- **Realtime**: Bun native WS (`realtime/routes.ts`) + Redis Pub/Sub backbone (multi-instance), EventBus (`card.*`, presence, chat), presence halos (`PresenceAvatars.tsx`), `change_seq` monotonic cursor (single integer across cards+lists, exact `nextCursor`).

## 4. Power features: search, reports, time, forms, automations, integrations

- **Search** (`modules/search/`): Postgres FTS (deliberate — OpenSearch/ES never adopted, see Decisions 2026-08-10 S12), cards/comments/attachments/wiki in one index, `saved_searches` (personal/shared, sidebar-pinned, JQL-style DSL roadmap), trigram indexes (migration `0042`).
- **Reports** (`modules/reports/`, `/projects/:id/reports` tabs): event-sourced `card_events` append-only log (moves, stage/sprint/assignment transitions) → cycle/lead time percentiles, sprint burndown/velocity, Cumulative Flow Diagram (stacked-area SVG from `board_snapshots`), stage distribution, workload, workspace portfolio health. Custom report builder (`report_definitions` + generic query engine).
- **Time tracking** (`time_logs`: minutes, billable flag, date): estimate vs actual per card/sprint/project, org Timesheets (`/timesheets`, filters, user/project summaries, CSV export).
- **Intake Forms + SLA** (`intake_forms` + `form_submissions`): admin JSON-schema builder (`FormBuilderModal`), public portal (`/forms/:slug`, internal or public with captcha/IP-throttle), submission creates Card in target List with reporter as Participant/Watcher, `sla_policies` (response/resolution breach tracking).
- **Automations**: (a) legacy board Butler rules (`automations`, kept); (b) current **Project Automation Engine** (5.6, `project_automation_rules` + per-(rule,action) RR cursors + `automation_rule_runs` skip-audit-log, migration `0032`): WHEN/IF/THEN (label router, Testing-handoff RR subtask), locked round-robin, AsyncLocalStorage loop guard + `automation:{ruleId}` system actors, DB partial-unique bounce guard, fill-if-unassigned, CRUD/toggle/paged-runs/dry-run/context APIs under `automation.manage`, builder page (`/projects/:id/automation`: templates, coverage auto-fix, run-history drawer). **Rule editing deferred** (create/delete only — Roadmap 5.7).
- **Webhooks + integrations**: org webhooks (HMAC-SHA256 `fetch` dispatch), Slack/GitHub/Drive catalog (mock OAuth) + **real GitHub webhook ingestion** (HMAC, no API dependency: ticket keys from branch/commit/PR text, PR open→In Review / merge→Done stage moves, bot-user comments, review badges, branch-create helper; per-repo AES-GCM secrets, same-repo-multi-org fan-out). GitLab deferred (same shape).
- **Importers**: Trello JSON full-board migration (lists/cards/checklists/labels+color map) + structured task import (with per-task `labels`), drag-drop wizard (`ImportModal`).
- **Marketplace + Developer API** (`marketplace_apps` + `installed_apps`, 5 seeded flagships; `/marketplace` catalog with verified badges + config modals) and API keys (`/admin/developer`, `bk_live_*` prefix, SHA-256 at rest, scopes + expiry).

## 5. Governance: RBAC, SSO, audit, billing, isolation

- **RBAC** (`PERMISSIONS_MATRIX.md`, `packages/shared-types/src/permissions.ts`, `seed.ts`): ~98 `resource.action` keys across platform/org/workspace/project/board/list/card/chat scopes; 4 seeded system roles (Org Owner, Org Admin, Member, Viewer) + org-member roles (Billing Manager, Workspace Admin) + per-org **team roles** (Lead/Developer/Tester — automation pools + `resolveDefaultAssignee` precedence: explicit > component rule > component lead > board > project > org) + **custom roles** (`/admin/roles` 10-category matrix). Enforcement: backend `requirePermission()` (one resolver shared by middleware + `GET /auth/me` `permissions[]` + `/auth/permissions`), frontend `usePermissions` + `<Can>`/`<CanAll>` (any-of vs all-of, destructive hides / reversible disables with reason, 403→`/me` refetch, 60s TTL + focus revalidate). Tests required per permission.
- **SSO/SCIM** (`/admin/sso`, `sso_configurations`): Okta / Entra ID / Google SAML / OIDC presets, WorkOS backend (no DIY SAML), domain routing, auto-provision on callback, SCIM 2.0 webhooks, `enforceSSO`, connection tester + SCIM token generator.
- **Audit + trash**: org audit log (`/admin/audit-logs`, filters + JSON inspector + CSV export, 730d retention batched prune; activity 365d; read notifications 180d; unread/starred never pruned), soft-delete everywhere (`deleted_at`) + Trash (`trash/routes.ts`, cascade deletes, `emptyTrash`, restore, days-remaining).
- **Billing** (`modules/billing/`, Stripe): plans Free/Pro/Business/Enterprise (seats/workspaces/boards/storage caps + feature flags), per-head seats with OCC `seatVersion`, guest overage items, idempotent webhooks (`processing` claim), invoices (`/admin/billing`), downgrade-blocked + expiry emails. Dedicated-DB-per-tenant tier flag (`isDedicatedDb` + URI) for enterprise upsell.
- **Isolation + limits**: app-layer `organization_id` predicates + membership checks everywhere (RLS deliberately unenforced — accepted risk, Decisions 2026-09-28; migration `0012` policies inert, `withOrgContext` removed 2026-10-03), token-bucket rate limiter (Redis Lua `EVALSHA`, fail-open with metric) + fleet concurrency semaphore (300s TTL), `clampLimit` paging caps (default 50/max 200), upload caps, org-prefixed cache keys, structured logs with `org_id`.

## 6. Platform ops: super-admin, mobile, theming

- **Super Admin** (`apps/super-admin`, `:5174`, platform-auth only): `/tenants` (search/filter, impersonate, dedicated-DB URI, plan/billing), `/users` (global search, cross-company roles, session revoke), `/plans` (caps/flags), health dashboards, global audit, announcements, rate-limit/abuse, GDPR export/delete.
- **Mobile** (`apps/mobile`, Expo RN): Login, Workspaces/Projects navigator, horizontal Kanban + quick-add, Card detail (comments, checklist toggle), Offline Queue (optimistic + replay `offlineQueue.ts`), push-device registration (`push_devices`, FCM/APNs via Expo Notifications). Phase 1 (read/comment/push) + Phase 2 (full edit/offline) both checked.
- **Theming**: 7 palettes (Light, Zinc Dark, Midnight OLED, Oceanic, Emerald, Synthwave, Nordic Frost) + 6 accents + custom HEX, CSS vars + Tailwind v4 tokens, `themeStore.ts` (system listener), `ThemeToggle` + `AppearanceModal` with live Kanban preview.
